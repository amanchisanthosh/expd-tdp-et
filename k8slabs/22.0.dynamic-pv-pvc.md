This lab matters because in real enterprise Kubernetes environments, static PV creation does **not scale**. Dynamic provisioning is what makes shared storage usable for teams, CI/CD, and stateful apps without admin intervention.

We’ll build a **realistic corporate-style lab**:

* 1 Control Plane (master)
* 2 Workers (node1, node2)
* NFS Server on **node1**
* Dynamic provisioning using **nfs-subdir-external-provisioner**
* Deploy **nginx** consuming dynamically created PVC

We will use the official provisioner from
Kubernetes SIG Storage

---

# 𐇠 Level 1 – Beginner (Big Picture)

Think like this:

* NFS server = Shared network disk
* StorageClass = Storage template
* PVC = Request form
* Provisioner = Auto storage creator
* Pod = App using storage

Flow:

```
Pod → PVC → StorageClass → NFS Provisioner → Creates folder in NFS → Mounts to Pod
```

No manual PV creation.

That’s dynamic provisioning.

# STEP 1 – Install NFS Server on node1

SSH into node2.

### Ubuntu/Debian:

```bash
sudo apt update
sudo apt install nfs-kernel-server -y
```

### RHEL/CentOS:

```bash
sudo yum install nfs-utils -y
```

---

## Create Export Directory

```bash
sudo mkdir -p /srv/nfs/kubedata
sudo chown -R nobody:nogroup /srv/nfs/kubedata
sudo chmod 777 /srv/nfs/kubedata
```

---

## Configure Exports

Edit:

```bash
sudo nano /etc/exports
```

Add:

```
/data/nfs *(rw,sync,no_subtree_check,no_root_squash)
```

Apply:

```bash
sudo exportfs -rav
sudo systemctl restart nfs-server
```

Verify:

```bash
showmount -e localhost
```

You should see:

```
/data/nfs *
```

---

# STEP 2 – Install NFS Client on All Nodes

On master, node1, node2:

Ubuntu:

```bash
sudo apt install nfs-common -y
```

RHEL:

```bash
sudo yum install nfs-utils -y
```

# STEP 3 – Deploy NFS Dynamic Provisioner

We’ll use:

kubernetes-sigs/nfs-subdir-external-provisioner

---

## Create Namespace

```bash
kubectl create namespace nfs-provisioner
```

---

## Create RBAC + Deployment YAML

Create file:

```bash
nano nfs-provisioner.yaml
```

Paste:

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: nfs-client-provisioner
  namespace: nfs-provisioner
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: nfs-client-provisioner-runner
rules:
  - apiGroups: [""]
    resources: ["persistentvolumes"]
    verbs: ["get", "list", "watch", "create", "delete"]
  - apiGroups: [""]
    resources: ["persistentvolumeclaims"]
    verbs: ["get", "list", "watch", "update"]
  - apiGroups: ["storage.k8s.io"]
    resources: ["storageclasses"]
    verbs: ["get", "list", "watch"]
  - apiGroups: [""]
    resources: ["events"]
    verbs: ["create", "update"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: nfs-client-provisioner-runner
subjects:
  - kind: ServiceAccount
    name: nfs-client-provisioner
    namespace: nfs-provisioner
roleRef:
  kind: ClusterRole
  name: nfs-client-provisioner-runner
  apiGroup: rbac.authorization.k8s.io
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nfs-client-provisioner
  namespace: nfs-provisioner
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nfs-client-provisioner
  template:
    metadata:
      labels:
        app: nfs-client-provisioner
    spec:
      serviceAccountName: nfs-client-provisioner
      containers:
        - name: nfs-client-provisioner
          image: registry.k8s.io/sig-storage/nfs-subdir-external-provisioner:v4.0.2
          volumeMounts:
            - name: nfs-client-root
              mountPath: /persistentvolumes
          env:
            - name: PROVISIONER_NAME
              value: example.com/nfs
            - name: NFS_SERVER
              value: <NODE1-IP>
            - name: NFS_PATH
              value: /data/nfs
      volumes:
        - name: nfs-client-root
          nfs:
            server: <NODE1-IP>
            path: /data/nfs
```

Replace `<NODE1-IP>`.

Apply:

```bash
kubectl apply -f nfs-provisioner.yaml
```

Verify:

```bash
kubectl get pods -n nfs-provisioner
```

Pod must be Running.

---

# STEP 4 – Create StorageClass

Create file:

```bash
nano storageclass.yaml
```

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: nfs-dynamic
provisioner: example.com/nfs
reclaimPolicy: Delete
volumeBindingMode: Immediate
```

Apply:

```bash
kubectl apply -f storageclass.yaml
```

Verify:

```bash
kubectl get sc
```

---

# STEP 5 – Create PVC

```bash
nano pvc.yaml
```

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: nginx-pvc
spec:
  accessModes:
    - ReadWriteMany
  storageClassName: nfs-dynamic
  resources:
    requests:
      storage: 1Gi
```

Apply:

```bash
kubectl apply -f pvc.yaml
```

Check:

```bash
kubectl get pvc
kubectl get pv
```

You will see:

* PVC → Bound
* PV auto-created

Check node1:

```bash
ls /data/nfs
```

You will see folder created automatically.

That is dynamic provisioning working.

---

# STEP 6 – Deploy Nginx Using PVC

```bash
nano nginx.yaml
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
spec:
  containers:
    - name: nginx
      image: nginx
      volumeMounts:
        - mountPath: /usr/share/nginx/html
          name: webdata
  volumes:
    - name: webdata
      persistentVolumeClaim:
        claimName: nginx-pvc
```

Apply:

```bash
kubectl apply -f nginx.yaml
```

Verify:

```bash
kubectl get pod nginx -o wide
```

SSH into node1 and create file:

# 𐄬 Level 3 – Expert View (Real Corporate Considerations)

### 1️⃣ NFS Is Single Point of Failure

This lab uses single node NFS.
In production:

* Use dedicated NFS server
* Or HA NFS cluster
* Or move to cloud storage

---

### 2️⃣ Performance Bottleneck

NFS is:

* Network dependent
* Latency sensitive
* Not ideal for high IOPS workloads (databases)

Good for:

* Shared content
* CI artifacts
* App uploads

---

### 3️⃣ Security Issues

`no_root_squash` is dangerous in production.

Proper config:

* Use specific CIDR
* Enable root squashing
* Restrict firewall

---

### 4️⃣ Reclaim Policy

We used:

```
reclaimPolicy: Delete
```

In enterprise:

Use `Retain` for production.

---

### 5️⃣ Better Alternatives (Enterprise)

* CSI drivers
* Cloud storage (EBS, Azure Disk, etc.)
* Distributed storage (Ceph, Longhorn)

# 𐏁 Final Golden Rule

Dynamic provisioning = **Storage on demand, zero manual PV management.**

But remember:

> Just because NFS works doesn’t mean it scales.

Use it for labs, shared storage, light workloads — not mission-critical databases.
